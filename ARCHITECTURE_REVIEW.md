# Проверка кода по Архитектуре 1.1

Дата: 15.09.2026. Проверены README.md, index.html и catalog.html. Проверка статическая, без запуска в браузере. Код не изменён. Актуальные требования изложены в документе «Наклейки - Архитектура проекта наклейки 1.1.docx».

Примечание после реализации: ниже сохранён результат исходной проверки до изменений. В последующей работе добавлены A–F, проверка количества, отдельный расчёт размещения, пробные поля и зазоры, до семи фактически необходимых листов с переключением, удаление с перерасчётом и увеличенный просмотр. Эти функции проверены тестами и в браузере. Реальные производственные параметры, контуры резки и оформление заказа остаются не реализованы; текущие численные параметры пробные. Отклонение целой партии при превышении лимита — принятое для прототипа поведение, требующее последующего согласования.

## Соответствует требованиям

Последующее уточнение пользователя: при превышении лимита партия добавляется частично — столько экземпляров, сколько удаётся разместить в десяти листах, с сохранением всех ранее выбранных наклеек. Затем окно показывает запрошенное, добавленное и оставшееся количество и предлагает оформить текущий заказ перед набором следующего. Это заменяет первоначальное отклонение партии целиком.

- Есть отдельные стартовая страница и каталог. На стартовой нет заказа и листа-макета (§1–2).
- Глобальный выбор размера и количества; двойной клик добавляет указанное количество; без размера выводится сообщение (§6–8).
- Повторное добавление увеличивает количество позиции с тем же изображением и размером (§6–7).
- Смена выбранного размера не меняет уже добавленные экземпляры (§8).
- Двойной клик по экземпляру в макете удаляет его и уменьшает количество в заказе (§9).
- Нет ручного перетаскивания, вращения или зеркалирования (§9).
- Каталог расположен слева, лист и заказ справа. У листа пропорции A4 (§1, §9).

## Расхождения реализации

1. Размеров четыре, A–D, вместо пяти A–E (§8). Ширины 25/50/75/100 пикселей встроены непосредственно в обработчик вместо конфигурации. Отсутствие физических миллиметров допустимо на этой стадии.
2. Нет отдельного Layout Engine (§9, §21). Массив orderItems содержит состав заказа, однако визуальные экземпляры отдельно добавляются и удаляются прямо в DOM. Полный макет не пересчитывается из состояния заказа.
3. Нет проверки печатной области, вместимости, промежутков между контурами, технических отметок и ограничений плоттера (§9). Обычное размещение HTML-изображений может вывести их за границы листа.
4. Есть только один постоянный контейнер листа (§11). Автоматическое создание необходимых листов, крупный выбранный лист, список остальных, переключение и предел семь листов не реализованы. Показ только необходимых листов пока невозможно полноценно проверить на многолистовом заказе.
5. Нет сценария оформления при достижении предела и начала следующего заказа после оформления (§11, §13).
6. Нет увеличенного просмотра по одиночному клику (§6).
7. Нет sticky-поведения листа (§10): position: relative не удерживает панель при прокрутке. Отдельной внутренней прокрутки правой панели нет, что соответствует требованию.
8. Возврат на страницу каталога не восстанавливает состояние (§1, §8). Восстановление после обновления также отсутствует, но его реализация сознательно отложена для стадии проектирования (§16).
9. Поле количества не проверяется обработчиком. Атрибут min=1 не мешает обработчику принять 0, отрицательное или дробное значение. При дробном количестве число визуальных экземпляров и значение в orderItems могут разойтись. Это нарушает согласованность состава заказа и макета (§7, §9).

## Ещё не реализованные части проекта

Это отсутствующие функции раннего прототипа, а не свидетельство отказа от Архитектуры:

- Предварительный каталог, поиск, теги, логотип-Agent, вход и обучающие видео на стартовой странице; социальные ссылки и GitHub (§2–5, §18–20).
- Структурированные фильтры с AND, поиск по названию и через Agent (§4–5).
- Итоговая сумма, кнопка оформления и её активация после первого добавления (§13).
- Гостевое оформление, аккаунт, перенос гостевого заказа, черновики, история, избранное (§13–16).
- Хранилище, сервер, платёжная интеграция, обработка изображений, производственные файлы и консолидация заказов (§12, §16–17, §21).

## Принцип показа листов

В версии 1.0 §11 уже содержал фразу «Показывается только фактически необходимое число листов». В версии 1.1 добавлен прямой пример: заказ на два листа показывает один развёрнутый лист и один в списке, без пустых миниатюр, вкладок, номеров или иных обозначений будущих листов 3–7.

## Приоритет дальнейшей реализации

Сначала выделить конфигурацию размеров и структурированное состояние заказа, проверить количество. Затем выделить расчёт размещения из UI, реализовать фактически необходимые листы и переключение. Численные производственные параметры остаются открытыми до тестов оборудования. Сохранение после обновления остаётся отложенным. Сценарий превышения лимита большой добавляемой партией и точное событие завершения оформления требуют отдельного согласования.
